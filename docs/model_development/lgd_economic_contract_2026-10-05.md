# Economic LGD cash-flow reconciliation implementation

October 5, 2026; model development, synthetic verification only. User authorized continuation. CPI ridge remains the working signed-source baseline; institutional approval and empirical economic labels remain open.

`src/cre_expected_loss/models/economic_lgd_contract.py` introduces a workout episode and a dated ledger entry contract. Episodes require explicit default/resolution dates, EAD/currency/basis, default definition, loss perspective and caller-verified ledger completeness/finalization. Entries require source, actual date, amount, category, transaction and underlying receipt IDs. Assumed payments, embedded payments, duplicates, unknown categories, currency/episode mismatch and dates outside the workout interval are rejected. Whole-loan perspective rejects lender loss-allocation reimbursement; verified institutional receipts are modeled separately. Completeness flags are input attestations, not proof supplied by the calculator.

The layer calculates nominal recovery/cost/loss totals and uncapped economic LGD using the existing calculator, ACT/365.25 time fractions and an explicitly labeled annual effective rate. Optional nominal cash-loss control totals must match the same basis within a supplied tolerance; Fannie accounting losses are not automatically that control total. Negative economic outcomes remain negative. Empty ledgers do not imply zero recovery. Source transaction records must resolve mixed/netted payments into documented non-overlapping entries; reversals require reconciliation before this nonnegative receipt/outflow contract.

No automatic rate selection, default-onset inference, recovery reconstruction, discounting of the reported loss ratio, baseline refit or expected-loss aggregation was added. Benefit/cost inclusion and cash-flow allocation remain caller evidence requirements. Actual Fannie records lack the full ledger needed to use this interface empirically. See `lgd_economic_feasibility_2026-10-05.md` for source gaps.

Tests verify timed recoveries and immediate costs against a direct present-value calculation, nominal reconciliation failure, unsupported inputs, duplicate underlying receipts, incomplete ledgers, perspective separation, negative outcomes and empty-ledger rejection. Full suite: 93 passed, five Pandoc-dependent checks skipped; one existing pandas warning. This is additive research code; baseline artifacts and raw data were untouched. Changes remain local/uncommitted.

Next data request: agreed PD-aligned default/episode definition; exposure-at-default reconciliation; dated borrower/property/insurance/lender receipts and workout payments with source IDs; finalization evidence; intended whole-loan or institution loss perspective; explicit rate convention. In their absence, only separately labeled synthetic or assumption-based sensitivity calculations are supportable.
